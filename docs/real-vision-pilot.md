# Real-vision preliminary pilot

Frozen design, October 30, 2026. Opt-in Gemini responses on synthetic sensor images;
the original offline commands remain software diagnostics. User authorized two
instances first, then ten after checking the two-instance output, with a $0 cap.
No 100-instance live experiment is authorized by this staged run.

## Access and cost

Verified official documentation on October 30, 2026:
- Model and image/structured-output support: https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash
- Free-tier input/output availability: https://ai.google.dev/gemini-api/docs/pricing
- Google-hosted compatibility API: https://ai.google.dev/gemini-api/docs/openai
- Billing tiers: https://ai.google.dev/gemini-api/docs/billing

Use `gemini-3.8-flash` for both roles, low reasoning effort, 2048 maximum completion
tokens, provider-default sampling, no tools/search/grounding. Requests go only to
Google's documented endpoint. The user confirmed a free-tier project with billing
disabled. The exact $0 policy relies on that provider-side account setting: a local
client cannot override a billing-enabled account. No paid fallback or automatic
retry exists. HTTP errors, including 429, latch the run stopped across resumes;
quota exhaustion is not automatically cleared. Missing usage remains unknown;
reported cost is a free-tier estimate, not an invoice audit. Request spacing is
at least seven seconds, which cannot guarantee compliance with account-specific
quotas. Secrets remain outside the repository and request logs.

## Experimental design

Use the reviewed ten-instance source dataset, seed 562, five hidden states of
each class, prior .5, acquisition reliability .75, approval gate .90. The first
two IDs are a prefix of those same ten, not a newly sampled two-instance dataset.
They need not be class balanced. Source manifest, resolved configuration, code
revision, uncommitted status, and recursive Python source hashes are saved.
The model alias may change remotely; each returned model identifier is retained.

Six conditions, paired within each base:

| Condition | Reports | Distinct acquisitions |
|---|---:|---:|
| single_raster | original PNG | 1 |
| exact_replay | three worker interpretations of the same PNG | 1 |
| resized_jpeg | original, 192x108 resize, JPEG quality 45 | 1 |
| cropped_replay | original, JPEG, crop [100,45,220,158] | 1 |
| cross_modal | original, crop, actual model-produced structured record of crop | 1 |
| independent_raster | three original PNG acquisitions | 3 |

Copies/transforms have unchanged acquisition identity. Independence is a property
of the synthetic generator conditional on Y, never inferred from image appearance.
No new related-view condition is introduced. Byte-identical independent acquisitions
retain separate IDs, calls, and roots. PNGs visibly marked MOCK identify synthetic
stimuli; actual API responses are not mock extraction.

Extraction requests contain only the image bytes and a fixed reading instruction.
They receive no fixture readings, hidden Y, oracle answers, acquisition values,
condition labels, or signal-check outputs. The structured record is generated by
a separate crop-reading model call; errors/nulls are preserved. Trusted code adds
its parent/root, never the model. Evaluator-only extraction accuracy compares the
model observation with the saved acquisition observation, separately from Y.

Three methods share the same worker report IDs and cached content in every paired
condition, and the same aggregator model/settings:
- `naive_llm`: general probability-estimation instruction and unconsolidated reports.
- `instruction_llm`: same reports plus explicit no-double-counting/ancestry instruction.
- `lineage_llm`: same instruction after trusted grouping by acquisition; conflicts,
  unknown ancestry, and unresolved root interpretations abstain.

All methods see trusted root metadata. Thus the naive model can spontaneously use
it; this is a baseline with no explicit deduplication instruction, not a forced
source-counting policy. The LLM supplies every non-null probability. Trusted code
never substitutes the analytical oracle. Descriptions and citation lists remain
in consolidated groups; total prompt lengths are not matched.

Hash/perceptual methods remain available in the offline transformation experiment,
not as extra live-model arms. The existing perceptual threshold stays frozen on
separate calibration roots. Its shared appearance templates and cross-modal limits
remain; root separation does not establish new-appearance generalization.

## Execution and resume

The key may be in `GEMINI_API_KEY` or the user-created local file
`~/.config/provenance-pilot/gemini-api-key`. Never commit credentials.

```sh
.venv/bin/python -m provenance_pilot.vision.run --instances 2 --output artifacts/real-vision-gemini
# Only after reviewing the successful two-instance stage:
.venv/bin/python -m provenance_pilot.vision.run --instances 10 --output artifacts/real-vision-gemini
# Repeat either command to resume compatible cached requests; no duplicate rows.
# Offline regeneration, refusing any uncached request:
.venv/bin/python -m provenance_pilot.vision.run --instances 10 --output artifacts/real-vision-gemini --replay-only
```

Requests and raw responses, tokens, returned model, latency, and schema failures
are stored by checksummed call identity. Config, evidence, or source-code changes
reject resume. An interrupted in-flight request has unknown outcome and is never
automatically reissued. Exports are atomic; one local process owns the run lock.
Changing only the requested prefix from two to ten reuses the initial calls.
For a stopped two-instance stage, do not run the ten-instance command.

## Analysis and limitations

Per-instance JSONL, summary JSON/CSV, paired differences JSON/CSV, SVG plot,
contact sheets, evidence index, provenance, extraction evaluation, and manifests
are local outputs. Saved contact sheets show all ten source instances; only the
requested prefix is evaluated. They are stimulus audits, not extraction results.

Probability/error/Brier means use valid outputs with numerators and denominators.
Oracle means cover all scheduled rows, including failures and abstentions. Decision
rates retain all scheduled eligible rows, including rows not attempted after a
stop; explicit attempted counts prevent these conservative rates being mistaken
for model performance. Stopped runs are incomplete and must not be reported as
successful ten-instance results. Citation lists do not reveal an LLM's internal
partition, so its matching errors are undefined. Only the trusted preprocessing
partition can be scored, and unavailable groupings stay null.

Paired percentile intervals resample entire base instances, preserving all
conditions/methods and cached derivatives. Pairwise complete probability metrics
can select different populations; coverage is reported. Undefined denominator
replicates are counted, not replaced by zero. These exploratory intervals describe
synthetic-instance variability conditional on these cached responses, not model
sampling uncertainty, natural-image performance, or general LLM defense efficacy.
Ten bases, two glyphs, known metadata, shared layouts, and no adversarial attacks
limit interpretation. Do not tune prompts/settings on pilot outcomes and then
present the same pilot as held-out confirmation.

## Actual attempt and subsequent repair (October 30)

The saved `artifacts/real-vision-gemini` run stopped on HTTP503 high demand: one
image timeout (not resent), one aggregator response rejected for empty citations,
and one503 response. The authenticated model lookup succeeded. Two aggregation
evaluations were attempted,34 scheduled rows were not attempted, and no valid
probabilities or resolved vision extractions exist. The ten-instance stage was
not started. No quota error was received and no paid fallback occurred.

Post-run testing fixed a stopped-resume bug that could overwrite attempted failures
with not-attempted rows. Atomic checksummed result checkpoints and CLI failed-state
handling were added. Those changes alter the code digest: the historical run is
preserved and correctly rejects execution with current source. For a later reviewed
replicate use a new output directory (for example `artifacts/real-vision-next`),
then reuse that directory only while code/config/source evidence remain compatible.
Do not clear the503 or quota latch automatically. The PDF addendum is regenerated
with `.venv/bin/python scripts/build_preliminary_report.py`; it deliberately refuses
to describe a changed live outcome without reviewing its narrative.
